Add HTTPS to ClipStage with Caddy

ClipStage speaks plain HTTP. On a shared network, anyone could read logins and session cookies. Caddy is a free, open-source program that sits in front of ClipStage and encrypts the traffic with a private certificate. You don’t need to buy a domain or a certificate.

Before you start

  • Run every command in Terminal on the server Mac, the one that runs ClipStage.
  • In your router, reserve a fixed IP for that Mac. If its address changes, everyone’s link and certificate break.
  • Note your current values, so you can roll back: 
    grep -E "CLIPSTAGE_BIND_HOST|CLIPSTAGE_COOKIE_SECURE" ~/Documents/ClipStage/.env
  • Don’t restart the app while an index run started from the app is going.

Find your address

ipconfig getifaddr en0
scutil --get LocalHostName

The first command prints the Mac’s IP on Wi-Fi. On Ethernet, try en1 or another interface. The second prints the Mac’s name. Its Bonjour name is that name plus .local.

  • IP address: simplest, and works from every computer. The examples below use 192.168.1.50, so replace it with yours. Caddy’s internal certificates should work for an IP, but if you get a certificate error, switch to a name.
  • Name: a router DNS name such as clipstage.lan is better if your router supports it. A .local name works from Macs but can be unreliable on Windows PCs.

Whatever you choose, editors must type exactly that address in the browser.

Steps

  1. Install Caddy

    brew install caddy

  2. Create the Caddy settings file

    Change 192.168.1.50 to your address first, then paste the whole block:

    cat > /opt/homebrew/etc/Caddyfile <<'EOF'
192.168.1.50 {
    tls internal
    encode gzip
    reverse_proxy 127.0.0.1:8000 {
        flush_interval -1
    }
}
EOF

    This is the same setup as Caddyfile.sample in the ClipStage folder, with your address. The flush_interval line keeps video previews from being buffered. If port 443 can’t be used, write 192.168.1.50:8443 on the first line and browse to https://192.168.1.50:8443.

  3. Start Caddy

    brew services start caddy

    Caddy now starts automatically when the Mac starts, and creates its private certificate authority.

  4. Trust the certificate on the server

    caddy trust

    It asks for the Mac’s password.

  5. Trust the certificate on every editor computer

    On the server, the certificate file is here:

    ~/Library/Application Support/Caddy/pki/authorities/local/root.crt

    It’s a public certificate, so it’s safe to share through a folder your editors can read. Change the destination folder to one of yours:

    cp "$HOME/Library/Application Support/Caddy/pki/authorities/local/root.crt" "/Volumes/SHARE FOLDER/ClipStage-root.crt"
    • Copy only root.crt. Never share root.key, which sits in the same Caddy folder. Anyone holding it could make certificates that those computers would trust.
    • Make the shared folder read-only for editors in your NAS or share permissions. Otherwise someone could replace the file, and editors would install the wrong certificate.

    Each editor opens ClipStage-root.crt from the share and installs it once:

    • Mac: double-click the file and add it to the login keychain. The System keychain needs an administrator. In Keychain Access, find the certificate (its name starts with Caddy Local Authority), double-click it, expand Trust, and choose Always Trust. The Mac asks for the editor’s own password.
    • Windows: double-click the file, choose Install Certificate, then Current User, and place it in Trusted Root Certification Authorities. Current User usually needs no administrator rights. Local Machine does.
    • Firefox keeps its own list, so import the file there too, or use Chrome, Edge or Safari.

    If an editor’s computer doesn’t allow installing certificates, ask your IT person. They can also push the certificate to all 25 computers at once. Skipping this step gives a browser warning.

  6. Test before changing anything else

    On one editor’s computer, open https://192.168.1.50. ClipStage must load with no certificate warning. On the server, also check that the app itself is up:

    curl -s http://127.0.0.1:8000/health

    It should print {"status":"ok"}.

    Don’t go on until the editor’s computer loads the page. If it doesn’t, use the troubleshooting list below.

  7. Switch ClipStage to HTTPS-only settings

    nano ~/Documents/ClipStage/.env

    Set these two lines. If a line already exists, change its value instead of adding a second one:

    CLIPSTAGE_BIND_HOST=127.0.0.1
CLIPSTAGE_COOKIE_SECURE=1

    Save with Ctrl+O, Enter, then exit with Ctrl+X. Restart the app:

    launchctl kickstart -k gui/$(id -u)/com.clipstage.api

    Tell the editors to use https://192.168.1.50 from now on. The old http://192.168.1.50:8000 link stops working.

  8. Final checks

    • Log in from an editor’s computer at the HTTPS address.
    • Make sure the app and the search engine aren’t open to the network: 
      lsof -nP -iTCP:8000 -sTCP:LISTEN
lsof -nP -iTCP:8108 -sTCP:LISTEN
      Both lines should show 127.0.0.1. If one shows *, it is reachable from the network.

If something goes wrong

  • The page won’t load or times out Caddy isn’t running or the port is blocked. Run brew services list | grep caddy, which should say started. Run lsof -nP -iTCP:443 -sTCP:LISTEN. If the macOS firewall asks about Caddy, allow it. Make sure the editor’s computer is on the same network.
  • “502 Bad Gateway” Caddy can’t reach the app. Run curl -s http://127.0.0.1:8000/health on the server. If it doesn’t print {"status":"ok"}, the app is down, or CLIPSTAGE_BIND_HOST is set to the network address only. Set it to 127.0.0.1 and restart the app.
  • Certificate warning That computer doesn’t trust Caddy’s certificate yet. Open ClipStage-root.crt from the share, install it again, and mark it Always Trust. Also type the address exactly as it appears on the first line of the Caddy file.
  • The page loads but login fails Note the exact message on screen. If it appeared right after step 7, check that CLIPSTAGE_COOKIE_SECURE=1 is only set while people use the HTTPS address.
  • You need Caddy’s own error messages Run brew services stop caddy, then caddy run --config /opt/homebrew/etc/Caddyfile. Errors print on screen. Press Ctrl+C to stop, then run brew services start caddy again.

Roll back

Put the old CLIPSTAGE_BIND_HOST value back in .env and remove the CLIPSTAGE_COOKIE_SECURE=1 line. Restart the app with the launchctl kickstart command from step 7. Then stop Caddy with brew services stop caddy.
