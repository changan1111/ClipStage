Run the ClipStage index at a set time and prove it ran

ClipStage’s index job is scheduled by a macOS launchd agent. These steps set your time, add a log that shows whether the job fired, and test the schedule before you rely on it.

Before you start

  • Run every command in Terminal on the Mac that hosts ClipStage.
  • That Mac must be on, awake and logged in at the scheduled time.
  • Commands assume the project is in ~/Documents/ClipStage. Adjust the path if yours differs.

Steps

  1. Add a heartbeat line to the script

    Open the script:

    cd ~/Documents/ClipStage
nano nightly_index.sh

    Paste this as line 2, directly under #!/bin/bash:

    echo "$(date '+%F %T') fired (user=$(id -un))" >> "$HOME/clipstage-heartbeat.log"

    It writes to your home folder, which macOS doesn’t block, so it records every launch even if the project folder is blocked. The top of the file should now look like this:

    #!/bin/bash
echo "$(date '+%F %T') fired (user=$(id -un))" >> "$HOME/clipstage-heartbeat.log"
# ClipStage v5.0 - scheduled index ...

    Save with Ctrl+O, Enter, then exit with Ctrl+X.

  2. Check the current time

    date

  3. Set a test time and a safe log path

    nano com.clipstage.indexer.plist

    Set the time to about 3 minutes from now, on a 24-hour clock. If date says 14:07, use hour 14 and minute 10:

    <key>Hour</key><integer>14</integer>
<key>Minute</key><integer>10</integer>

    In the same file, change both log paths from __CLIPSTAGE_HOME__/launchd.log to a location macOS doesn’t block:

    <key>StandardOutPath</key><string>/tmp/clipstage-launchd.log</string>
<key>StandardErrorPath</key><string>/tmp/clipstage-launchd.log</string>

    Save and exit.

  4. Install it

    bash install_nightly.sh

    Editing the plist alone does nothing. launchd reads a copy in ~/Library/LaunchAgents, and this script refreshes that copy.

  5. Confirm launchd loaded your time

    plutil -p ~/Library/LaunchAgents/com.clipstage.indexer.plist | grep -E "Hour|Minute"

    It should print your test hour and minute.

  6. Wait for the test time, then read the logs

    cat ~/clipstage-heartbeat.log
tail -20 indexer.log
cat /tmp/clipstage-launchd.log
    • Heartbeat line is there: the schedule works. Read indexer.log for any other error.
    • No heartbeat: launchd or macOS didn’t start the job. Share the contents of /tmp/clipstage-launchd.log.

    Don’t use launchctl kickstart for this test. It starts the job immediately, so it doesn’t prove the schedule works.

  7. Set your real time

    Repeat steps 3 and 4, changing only Hour and Minute. For 2:30 AM:

    <key>Hour</key><integer>2</integer>
<key>Minute</key><integer>30</integer>
    bash install_nightly.sh

    The next morning, run cat ~/clipstage-heartbeat.log to confirm it fired overnight.

Optional: keep the Mac awake for the run

A sleeping Mac won’t wake for the job, and a powered-off Mac skips it. This wakes or starts the Mac 5 minutes before a 2:30 AM run:

sudo pmset repeat wakeorpoweron MTWRFSU 02:25:00

If it still doesn’t run

  • Job isn’t loaded Run launchctl print gui/$(id -u)/com.clipstage.indexer. If it says “Could not find service”, run bash install_nightly.sh.
  • No heartbeat, and the launchd log says “Operation not permitted” macOS is blocking ~/Documents for background jobs. Move the folder to ~/ClipStage and re-run bash install_nightly.sh, or give /bin/bash Full Disk Access in System Settings.
  • Background item is switched off In System Settings → General → Login Items & Extensions, make sure ClipStage is allowed to run in the background.
  • Heartbeat is there, but indexer.log shows an error
    • “TYPESENSE_KEY is not set”: .env is missing or not next to the scripts.
    • “Typesense did not start”: check /tmp/typesense.log.
    • “Indexer already running”: a stale index_status.json, or someone is running Sync Index from the app.
    • “No matching volume is mounted”: the NAS didn’t mount, or macOS is blocking network volumes for /bin/bash.
