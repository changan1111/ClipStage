ClipStage backup and recovery runbook

Search • Stage • Edit — get ClipStage running again on a new Mac after an outage

How it fits together A. Prepare now B. Recover C. Editors D. Scripts and settings Troubleshooting
Not yet tested end to end. Do one trial restore on the new Mac while the old one still works, so the first real attempt is not during an outage.

How it fits together

ClipStage keeps its data in four places. Backing up the right ones is what makes recovery fast.

WhatWhere it livesRebuilt from the NAS?
Notes, details, use counts, audit log, hidden flagsclipstage.db (backed up nightly to backups/db/)No. Back this up.
Editor listeditors.jsonNo. Back this up.
Search index with durationsTypesense (~/typesense-data)Yes, but a full scan takes about 3 hours. A snapshot restores it in minutes.
Thumbnailsstatic/thumbsYes, but regenerating takes days at 5,000 a night.
Settings and keys.envNo. Back this up.
Use a folder name with no spaces on the new Mac, for example ~/ClipStage. A space in the folder name broke the first install.

A. Prepare now, while the old Mac works

Do this once. The nightly job then keeps it current.

cd "/Users/JANAM_EDIT_08/Documents/Karthik/ClipStage"
./clipstage.sh status

The progress bar in the app should be gone and "Full run" should show a date. A snapshot does not need another scan. It only exports what the scan already built.

Create snapshot_index.py in the ClipStage folder, next to indexer.py. The full file is in section D.

./clipstage_run.sh snapshot_index.py

It should print Backup written: ... (23,092 clips). A file named clips_<date>_<time>.jsonl appears in backups/.

open -e nightly_index.sh

Find the line that runs backup_db.py near the bottom. Add these lines just above it, then save:

"$PYTHON" snapshot_index.py || clipstage_alert "Index snapshot failed - see indexer.log"

No reinstall is needed. The nightly job reads this file each time it runs. The newest 7 snapshots are kept.

A backup on the same disk will not survive a dead disk. Copy these to a NAS folder or an external disk regularly:

  • .env
  • backups/db/ (database copies and editors.json)
  • the newest backups/clips_*.jsonl
  • static/thumbs

To send the database backups to the NAS automatically, set this in .env:

CLIPSTAGE_BACKUP_DIR=/Volumes/SHARE FOLDER/clipstage-backups

The index snapshots stay in the local backups folder, so copy those by hand or with a scheduled copy.

B. Recover on the new Mac

Follow these in order. Each step needs the one before it.

cd ~
unzip ClipStage-v5_1_3-mac-windows.zip
cd ~/ClipStage
bash install-mac-host.sh

If the zip unpacks into a different folder name, move or rename it to ~/ClipStage first. When the installer offers the first index, skip it.

Use the same names as before: EDIT, EDIT2, INGEST, PLAYOUT, DIGITAL, SHARE FOLDER, TRANSCODER. The saved clip paths depend on them. The installer's mount step does this.

cd ~/ClipStage
./clipstage.sh stop

If stop is not accepted, continue. Step 5 restarts everything anyway.

  • .env. Check that any paths inside still fit this Mac.
  • the latest clipstage-YYYY-MM-DD.db from backups/db/, renamed to clipstage.db
  • editors.json
  • the newest clips_*.jsonl into backups/
  • the thumbnails into static/thumbs

./clipstage.sh restart
sleep 30
./clipstage.sh status

The API and Typesense should both show running. If not, see Troubleshooting.

ls backups/clips_*.jsonl
./clipstage_run.sh indexer.py --restore backups/clips_YYYYMMDD_HHMMSS.jsonl

Replace the file name with the newest one from the ls list. This takes minutes. It also re-applies notes, use counts and hidden flags from clipstage.db.

./clipstage.sh index

This reuses the saved durations and only checks new or changed files. Watch progress in the app or with ./clipstage.sh logs.

  • Open http://<new-ip>:8000 and sign in.
  • Search for a word and confirm results appear.
  • Confirm thumbnails show on the clips.
  • Open a few clips you know have notes and confirm the notes are there.
Keep the Mac awake while it serves editors: turn off automatic sleeping on the power adapter, keep it plugged in, and stay logged in (lock the screen instead of logging out). The services stop if the user logs out.

C. Point the editors at the new Mac

The new Mac has a different address than the old 10.1.10.165. Choose one way:

Keep the old address. Ask your network admin to reserve 10.1.10.165 for the new Mac once the old one is off. Editors change nothing.

Use a new address. Tell editors the new address. On each editor Mac, run:

bash install-mac-editor.sh --host <new-ip>

Windows editors: follow INSTALL-QUICKSTART.md (install-win-editor.ps1).

Keep only one Mac live for editors at a time. Two live systems would split notes and staging between them.

D. Scripts and settings

Everything you need to create or change, with the file name and where it goes. Use Copy, then paste.

1. snapshot_index.py (new file)

Where: the ClipStage folder, next to indexer.py.

Create it: in Terminal run nano snapshot_index.py, paste the code, press Ctrl+O, Enter, then Ctrl+X. Avoid TextEdit unless it is set to plain text.

snapshot_index.pysave in the ClipStage folder
#!/usr/bin/env python3
"""
ClipStage - write a snapshot of the search index (durations included) to backups/clips_<time>.jsonl.

    ./clipstage_run.sh snapshot_index.py

Restore on a new machine (after install + same volume names):
    ./clipstage_run.sh indexer.py --restore backups/clips_YYYYmmdd_HHMMSS.jsonl

Keeps the newest 7 snapshots. Refuses to write an empty snapshot.
"""
import sys

import indexer  # importing does not start a scan (main code is under __main__)

docs = indexer._load_existing_docs()
if not docs:
    print("Index is empty or unreachable - no snapshot written.")
    sys.exit(1)
indexer.backup_existing(docs, keep=7)

Run it: ./clipstage_run.sh snapshot_index.py. It writes backups/clips_<time>.jsonl and keeps the newest 7. It refuses to write an empty snapshot. Run it after a scan finishes, because a snapshot taken mid-scan only holds the clips indexed so far.

Restore with it: ./clipstage_run.sh indexer.py --restore backups/clips_<time>.jsonl

2. nightly_index.sh (edit the existing file)

Where: the ClipStage folder. Open it with open -e nightly_index.sh.

What to change: add the two snapshot lines just above the existing backup_db.py line at the bottom. The block below shows the end of the file after the change. Add only the snapshot lines and leave everything else as it is.

nightly_index.shadd to the end of the file
# ...existing lines above...

# Nightly snapshot of the index (for quick rebuild on a new Mac)
"$PYTHON" snapshot_index.py || clipstage_alert "Index snapshot failed - see indexer.log"

# Nightly copy of clipstage.db (notes/details/audit - cannot be rebuilt). See backup_db.py.
"$PYTHON" backup_db.py || clipstage_alert "clipstage.db backup failed - see indexer.log"

No reinstall is needed. launchd runs this file directly each night at 17:00.

3. .env (add lines)

Where: the ClipStage folder. It is a hidden file, so open it with open -e .env.

What to change: add the lines you want. Each is optional. If a name already exists in the file, edit that line instead of adding a second one.

.envadd to the file
# Send database backups to the NAS (keep a copy off this Mac)
CLIPSTAGE_BACKUP_DIR=/Volumes/SHARE FOLDER/clipstage-backups

# New thumbnails made by the nightly job (default 5000)
CLIPSTAGE_THUMBS_LIMIT=5000

# Parallel duration reads during a scan (default 8, optional)
CLIPSTAGE_PROBE_THREADS=8

Restart after changing .env: ./clipstage.sh restart. The nightly job reads it on its next run without a restart.

4. Commands you will use again

Terminalrun inside the ClipStage folder
./clipstage.sh status                     # is everything running
./clipstage.sh restart                    # restart the API
./clipstage.sh logs                       # watch the indexer
./clipstage.sh index                      # start an index run
./clipstage.sh thumbs 25000               # make up to 25,000 new thumbnails
./clipstage_run.sh snapshot_index.py      # save an index snapshot now
./clipstage_run.sh indexer.py --reprobe   # retry blank durations

Troubleshooting

SymptomLikely cause and fix
Status shows the API as NOT runningRead the newest log lines: tail -n 20 api.log. If you see "Operation not permitted", the folder is inside Documents or has a space in its name. Move it to ~/ClipStage and reinstall the services with bash install_api_service.sh, bash install_nightly.sh and bash install_mountwatch.sh.
Browser says "refused to connect"The API is not running. Same fix as above. Test it in the foreground with ./start_clipstage.sh to see the real error.
Restore finds no clips on screenCheck that Typesense is running and that .env has the same TYPESENSE_KEY as before.
Clips show but will not play or stageThe NAS volumes are not mounted under the same names. Run bash mount_volumes.sh and check /Volumes.
Thumbnails missingCopy static/thumbs back, or run ./clipstage.sh thumbs 25000. The nightly job also makes 5,000 a night.
Duration shows "-" on some clipsThe scan has not reached them, or the file could not be read. Run ./clipstage_run.sh indexer.py --reprobe.
Commands assume the default ClipStage v5.1.3 layout. Folder names, volume names and the old address are from your setup. Edit them here if your setup changes.
